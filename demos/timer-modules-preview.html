TimerModules

A snap-together Gantt chart for timers — with boolean logic gates instead of conventional dependencies.

Rooted from OPerationsHOS Timer module · NightGard namespace · GPL v3 · Concept preview 2026-05-19

§1What this is

Most timer apps give you one timer at a time. Most Gantt charts give you a static plan. TimerModules is the intersection: a live Gantt chart where each row is a running timer, the connectors between them are snap-together bricks, and the connector family includes boolean logic gates (AND, OR, NOR, NOT) alongside the conventional project-management dependency types (FS, SS, FF). Most PM software has one or the other — TimerModules has both, and they compose.

§2Brick palette

Three families of Lego pieces. Snap them onto the Gantt canvas to build whatever shape you need.

Family 1 — Functional
Timer
⏱ Timer block

The main brick. Has a duration, a state (idle / running / paused / done), and inputs/outputs. Inherits the analog dial UI from OPerationsHOS's TimerSectionView.

Family 2 — Connectors
Logic gates + PM types
Logic gates · v1.0
∧ AND ∨ OR ¬ NOT ↓ NOR
Logic gates · deferred to v1.1+
⊼ NAND ⊕ XOR ⊙ XNOR
PM dependency types · v1.0
FS · Finish → Start SS · Start → Start FF · Finish → Finish Lag/Lead · offset
PM dependency types · deferred
SF · Start → Finish (rare)
Family 3 — Supplemental
Annotations & side effects
≡ Note ◆ Marker ▶ Trigger ⚡ Action ▢ Group (stretch)

Note & Marker = pure annotation. Trigger = entry-point brick that starts a flow. Action = side-effect brick (sound, notification, log entry, deep-link out).

§3Live demo — three timers, one logic gate

Press play to watch three Timer bricks run. The logic-gate connector waits for its inputs to complete, then routes a signal to the third timer's start. Switch the gate type to see how the same three timers behave under different boolean rules.

Gate: AND Prep: idle Setup: idle Run: idle Gate output: false
AND — the Run timer starts only when both Prep and Setup have finished. Sync barrier pattern, common in project-management Gantts as a "merge point."

§4Roadmap snapshot — wanted features

What's already visible in this demo vs. what's still wanted. Iterates as we settle decisions.

Demoed

Timer brick (Functional)

Bar with duration, idle/running/done states. Three instances on screen.

Demoed

Logic-gate connector

AND/OR/NOT/NOR live-switchable. Gate sits between predecessor outputs and downstream timer start.

Partial

PM dependency types

FS implicit in the demo (Run starts after gate fires). SS, FF, Lag/Lead not yet visible.

Wanted

Drag-and-drop palette (user-Lego)

Drag bricks from the palette onto the canvas. Snap into rows. Connect outputs to inputs with click-drag wires.

Wanted

Trigger brick

Entry-point brick — manual button / scheduled clock / external event. Every flow needs a start.

Wanted

Action brick

Side-effect at end of timer or gate fire: sound, notification, journal log, deep-link.

Wanted

Marker / Note

Milestone diamond on the time axis, sticky-note attached to bricks.

Wanted

Multiple gates per flow

Chain gates: (A AND B) OR (C NOR D). Demo currently shows one gate; production app will compose.

Open

Developer-Lego vs. user-Lego

Does the user assemble bricks at runtime, or does the app ship with pre-composed layouts? Demo leans toward user-Lego.

Open

Persistence model

SwiftData / @AppStorage / in-memory. Demo doesn't persist anything across reload.

Open

Distribution ambition

Personal use only · free App Store release · book appendix. Decision affects ship-prep scope.

§5Glossary

Reference vocabulary for describing revisions. Refer to bricks by name when you want changes.

Brick
A snap-together piece of the app — timer, connector, or supplemental.
Functional brick
Family 1 — the Timer block. Runs time.
Connector brick
Family 2 — wires bricks together. Two sub-families: logic gates + PM dependencies.
Supplemental brick
Family 3 — annotation (Note, Marker) or side effects (Trigger, Action).
Logic gate
Boolean combination of input signals: AND, OR, NOT, NOR. The unique twist vs. conventional Gantt tools.
PM dependency
Project-management edge type: FS (Finish-to-Start), SS (Start-to-Start), FF (Finish-to-Finish), Lag/Lead.
Canvas
The Gantt surface where bricks are placed and connected. Time runs left to right.
Row
A horizontal track on the canvas. One timer per row (typically).
Trigger
Entry-point brick. Without one, the canvas is a diagram, not a runnable program.
Action
Side-effect brick. Fires when an upstream timer or gate signals.
Composition
Logic-gate sub-family + PM-dependency sub-family combine: "B starts (FS) when A AND C both finish (AND gate)."
